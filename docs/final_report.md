# 2D Autonomous Drone Delivery: Original Optimization Report

This report documents the original optimization-only foundation. The project
has since added a separate tabular Q-learning proof of concept; see the root
README and `results/rl/` for reproducible learning experiments.

## 1. Introduction

This project plans a 2D delivery-drone route through a bounded map containing circular no-fly zones. The mathematical optimization layer is the primary deliverable. Reinforcement learning, 3D simulation, and flight-control software are outside the current scope.

## 2. Problem Formulation

The start point `P_0` and destination `P_(N+1)` are fixed. The decision variables are the `N` intermediate waypoints:

`z = [x_1, y_1, ..., x_N, y_N]^T`.

For consecutive points, `d_i = ||P_(i+1) - P_i||` and `D(z) = sum_i d_i`. The implementation evaluates time as `T(z) = D(z) / v` and energy as `E(z) = P(v) T(z)`, where `P(v) = c_0 + c_1 v + c_2 v^2`.

The default objective is the weighted time-energy objective used by both algorithms:

`F(z) = w_T T(z) + w_E E(z) + w_S S(z)`.

The optional smoothness term is `S(z) = sum_i ||P_(i+1) - 2P_i + P_(i-1)||^2`. Its analytical gradient is implemented in `src/objective.py`.

## 3. Constraints

All constraints use standard form `g_j(z) <= 0`:

- Battery: `E(z) - B_available <= 0`, where `B_available` preserves the reserve state of charge.
- Time: `T(z) - T_max <= 0`.
- Buffered no-fly zones: `(r + safety_margin + extra_clearance)^2 - ||P_i - C||^2 <= 0`.
- Interior segment samples use the same buffered obstacle constraint.
- Workspace: lower and upper bounds for every waypoint coordinate.

The effective safety radius is larger than the raw obstacle radius. The final checker uses exact point-to-segment distance, while the optimizer uses interior samples as a differentiable penalty approximation.

## 4. Penalty Method and Feasibility

The algorithms minimize:

`F_penalty(z) = F(z) + rho sum_j max(0, g_j(z))^2`.

Penalty optimization is not treated as proof of feasibility. Every initial and final route is checked independently for fixed endpoints, workspace bounds, buffered waypoint clearance, exact segment clearance, battery, and maximum time. Violations and minimum clearance are recorded in `results/metrics/`.

## 5. Gradient and Hessian

The distance gradient uses the two adjacent segment contributions for each intermediate waypoint. The implementation uses an epsilon in segment lengths to avoid division by zero. Penalty gradients are included for battery, time, no-fly, sampled segment, and workspace constraints.

The Hessian is calculated by central finite differences of the implemented penalized gradient and then symmetrized. `src/analysis.py` reports eigenvalues, minimum and maximum eigenvalues, symmetry error, curvature classification, and the condition number only when the Hessian is positive definite. An undefined condition number is reported as `null`, not forced into the SPD formula.

## 6. Convexity, Lagrangian, and KKT

The distance objective is convex on regions without degenerate segments, and the quadratic smoothness term is convex. However, the buffered circular no-fly feasible regions are complements of disks and are generally non-convex and disconnected. Therefore, the complete constrained problem is non-convex; a local KKT point is not automatically a global optimum.

For `g_j(z) <= 0`, the Lagrangian is:

`L(z, mu) = F(z) + sum_j mu_j g_j(z)`, with `mu_j >= 0`.

The KKT conditions are stationarity, primal feasibility, dual feasibility, and complementary slackness. The generated constraint report classifies each constraint as active, inactive, or violated using a numerical tolerance. Multipliers are not fabricated from a penalty coefficient; the report records the observable constraint status and explains that exact multiplier estimation would require solving the stationarity system for the active set.

## 7. Algorithms and Fair Comparison

Gradient Descent uses `z_(k+1) = z_k - eta grad(F_penalty)`. Heavy-Ball uses `z_(k+1) = z_k - eta grad(F_penalty) + beta(z_k - z_(k-1))`. Both are implemented manually, use the same initial waypoint vector, objective, constraints, penalty coefficient, stopping tolerance, and maximum iteration budget for each paired run. Histories include penalized objective, gradient norm, feasibility flag, maximum violation, runtime, and final route metrics.

## 8. Experiments

Running `python src/experiments.py` performs:

1. Basic scenario 0 optimization.
2. Learning-rate sensitivity for `eta` in `{0.005, 0.01, 0.02}`.
3. Heavy-Ball momentum sensitivity for `beta` in `{0.7, 0.9, 0.95}`.
4. Waypoint-count study for `N` in `{5, 10, 20, 40}`.
5. Initialization sensitivity for straight, offset, and perturbed initial paths.
6. Hessian analysis at the initial and final points.

The output is empirical and regenerated by the runner, not invented in this document. The study data is stored in `results/metrics/experiment_study.json`.

Not every non-convex run is expected to succeed: the study retains infeasible parameter/initialization outcomes with their violation message. The main two-obstacle comparison and the separate single-obstacle case are checked for feasible final routes; sensitivity results are evidence about robustness, not selectively filtered successes.

## 9. Required Plots

The runner generates initial/final trajectory plots, separate GD and Heavy-Ball convergence plots, a combined objective plot, gradient-norm convergence, constraint-violation convergence, and objective versus waypoint count. Safety buffers are drawn separately from raw no-fly zones.

## 10. Real-World Limitations

The model is a planning abstraction, not flight software. Energy is simplified and omits wind, payload changes, acceleration, altitude, temperature, battery ageing, and motor/propeller efficiency. Speed is constant, the map is 2D, no-fly zones are static, and trajectories are discretized. Penalty methods can return approximate rather than exact feasibility, and non-convex geometry creates local-minimum and initialization sensitivity. A practical extension would use dynamic replanning, a richer energy model, uncertainty-aware clearance, and model-predictive control.

## 11. Reproducibility

From the project root on Windows:

```powershell
.venv\Scripts\python.exe src\experiments.py
```

The source is organized into `src/`, scenario data is in `data/`, dataset generation is in `scripts/`, and this report/specification are in `docs/`. The implementation deliberately does not use `scipy.optimize.minimize` or an RL algorithm.
